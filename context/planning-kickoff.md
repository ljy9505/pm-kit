# 기획 작성 킥오프 — 초안 쓰기 전에 이걸 먼저 (엣지케이스 강제 발굴)

> 기획서 초안을 쓰기 **전에** `.claude/context/domain-context.md`와 함께 이 파일을 참조한다.
> 목적: 빈 문서에서 바로 쓰지 말고, 빈틈을 먼저 드러낸 뒤 쓰기 위함.
> 프로젝트별로 커스터마이즈하려면 이 파일을 `.claude/context/planning-kickoff.md`로 복사해 수정한다.

## STEP 0. 전제부터 꺼내기 (질문의 각도 점검)

빈틈을 묻기 전에, 이 기획이 딛고 있는 전제부터 적는다. 각도가 틀리면 그 아래 문서는 정확하게 틀린 채로 완성된다.

```
초안을 쓰기 전에, 이 기획이 깔고 있는 전제를 3~5개 뽑고 각각에
[확인됨 / 추정 / 모름]을 붙여라. 그다음 이 접근에서 내가 안 보고 있는 관점과,
최근 변화 중 이 전제를 흔드는 것이 있는지 짚어라.
근거를 댈 때는 링크가 아니라 출처명·제목·발행일을 적어라.
```

- '추정·모름'은 `decisions.md` 오픈 이슈로 옮기고, 그 위에 세운 기능에 표시한다.
- 비교("무엇이 무엇과 다른가")보다 변화("무엇이 왜 뒤집히고 있는가")를 먼저 본다.

## STEP 0+. 어드민 범위 확정 (역질문보다 먼저)

초안·역질문 전에 어드민 포함 범위부터 못 박는다:
> "이 기획에 **어드민(관리자) 기능도 포함**할까요? — ⓐ 서비스+어드민 함께 / ⓑ 서비스만(어드민은 기존으로 충분) / ⓒ 어드민만"

왜: 서비스가 만드는 데이터는 결국 **어드민에서 조회·수정·삭제·상태변경**해야 한다. 서비스만 기획하면 "이 데이터 관리 화면이 없다"가 출시 후 터진다.
- ⓐ면 STEP 3의 권한 CRUD를 **서비스+어드민 짝**으로 채운다.
- ⓑ면 이 데이터가 **기존 어드민으로 관리 가능한지** 확인하고, 불가하면 갭을 오픈 이슈로 남긴다.

## STEP 1. 작성 전 역질문 (Claude가 나에게 되묻게 하기)

작성 지시에 이 문장을 붙인다:

```
초안을 쓰기 전에, 아래에서 '아직 정의되지 않은 것'을 5~7개 질문으로 먼저 되물어라.
내가 답한 뒤에야 초안을 작성한다. 추측으로 채우지 마라.
- 권한별 가능/불가능 액션 (각 역할이 못 하는 것)
- 허용되지 않는 상태 전이와 그때의 시스템 동작
- 실패 / 중복 / 동시성 처리
- 빈 상태 / 최대치 / 경계값
- 외부 연동 실패 시 처리
- 데이터 삭제 시 이력 보존·되돌리기
- 이 기능이 만드는/바꾸는 데이터를 어떤 어드민 권한이 CRUD 하는가
- 성공을 무엇으로 세는가 (이벤트가 심겨 있는가)
- 이 기능이 보내는 알림의 조건·대상·수신 거부
- 배포 시점의 기존 데이터와 진행 중인 건 처리
- 사람이 손으로 처리해야 하는 케이스
- 새로 수집하는 개인정보와 고지 필요 여부
```

## STEP 2. 초안 작성 규칙

- 문서 순서: **정책서 → 기능 정의서 → 화면 설계서** (어드민/관리 세트 먼저, 그다음 사용자용)
- 모든 예외는 **`조건 → 시스템 동작 → 화면에 보이는 것`** 3단으로 쓴다.
- 용어는 `domain-context.md` / glossary를 따른다. 임의 명명 금지.

## STEP 3. 권한 × CRUD 매트릭스 (반드시 채우고, 빈칸 = 구멍)

각 리소스마다 아래 표를 만든다. `-`(불가) 칸에는 **"어떻게 막는지"**까지 쓴다.

### 예시: 리소스 = "수강 신청"

| 역할 | Create(신청) | Read(조회) | Update(수정) | Delete(취소) |
|---|---|---|---|---|
| 매니저 | ✅ 대리신청 | ✅ 전체 | ✅ 상태변경 | ✅ (사유 기록) |
| 강사 | — (버튼 비노출) | ✅ 담당분만 | — | — |
| 수강생 | ✅ 본인 | ✅ 본인만 | — (마감 후 잠금) | ✅ 결제 전만, 이후 환불규정 |
| 게스트 | — (로그인 유도) | — | — | — |

> `—` 칸의 "어떻게 막는지"(버튼 비노출/잠금/리다이렉트)가 비면, 그게 권한 우회 엣지케이스다.

**어드민 포함(ⓐ)이면 어드민 역할도 이 표에 함께 넣는다.** 서비스가 만든 데이터를 어드민이 관리(수정·삭제·상태변경)하는 CRUD가 비면 관리 화면 누락이다.

## STEP 4. 넘기기 전 셀프 게이트

프로토타입/개발로 넘기기 전 아래를 스스로 확인 → 그다음 `planning-reviewer` 에이전트 실행:
- [ ] 모든 예외에 `조건 → 동작 → 화면`이 있다
- [ ] 리소스마다 권한 CRUD 매트릭스가 있고 빈칸이 없다
- [ ] 상태 전이표에 "허용 안 된 전이"가 명시돼 있다
- [ ] 외부 연동마다 "실패 시 처리"가 있다
- [ ] (어드민 포함 시) 서비스 데이터마다 그걸 관리하는 어드민 기능(CRUD)이 짝으로 있다
- [ ] 모르는 것을 "오픈 이슈"로 적어뒀다 (모른다는 걸 아는 것)
- [ ] 모든 성공 지표에 "세는 방법"이 붙어 있다
- [ ] 알림마다 발송 조건, 대상, 수신 거부가 있다
- [ ] 배포 시점의 기존 데이터·진행 중인 건 처리를 정했다
- [ ] 자동으로 안 되는 케이스를 처리할 어드민 기능이 있다
- [ ] 문제 생겼을 때 끌 수 있는 스위치와 중단 기준이 있다
