## 1. 먼저 화면의 «모드»를 정한다 (한 줄, 문서엔 안 씀)

impeccable의 핵심 아이디어 하나만 가져왔다. **화면마다 «성공»의 정의가 다르므로, 모드를 먼저 못 박으면
밀도·모션·카피의 기준이 매번 새로 흔들린다.** 제품 전체가 아니라 **화면 한 장마다** 정한다.

| 모드 | 이 화면의 성공 | 기준이 이렇게 갈린다 |
|---|---|---|
| **설득** (랜딩·소개·모집 페이지) | 방문자가 **결정하고 행동**한다 | 첫 화면에 값어치와 행동이 다 있어야. 이미지·연출이 제품의 일부 |
| **처리** (관리자·목록·폼·대시보드) | 사용자가 **일을 끝낸다** | 훑기·일관성·관례가 표현보다 위. 연출은 상태를 말할 때만 |
| **읽기** (약관·가이드·공지·도움말) | 사용자가 **이해한다** | 구조와 가독성이 전부. 한 줄 길이·제목 위계가 디자인 |
| **체험** (갤러리·수상작·포트폴리오) | **작품이** 주인공이다 | UI가 뒤로 물러난다. 첫 화면부터 콘텐츠가 이끈다 |

> **모드는 «제품»이 아니라 «그 화면»이 정한다.** 관리 도구의 소개 페이지는 여전히 **설득**이고,
> 브랜드 사이트의 약관 페이지는 여전히 **읽기**다.
>
> 가장 자주 틀리는 자리: **처리 화면을 설득 화면처럼 꾸미는 것.** 관리자 목록에 큰 히어로 띠·장식 연출·
> 브랜드 면을 넓게 깔면, 승인·반려 버튼이 그 안에 묻힌다. 처리 화면에서 브랜드는 **주 버튼·현재 선택·상태
> 표시**에만 나오고, 나머지는 무채색이다.

## 2. AI 프로토타입이 반사적으로 내놓는 것 (지시할 때 미리 막는다)

프롬프트에 "예쁘게"라고만 쓰면 아래가 그대로 나온다. **금지가 아니라 «기본값»이다** — 기획 의도가 그걸
요구하면 써도 된다. 다만 *의도 없이 나왔다면 그건 결정을 안 한 것*이다.

### 2-1. 구성

- **똑같은 카드 3장 가로 배치**로 섹션을 만드는 것. (참여 방법 1·2·3, 기능 소개 3종 ...)
  → 순서가 있으면 **연결선 있는 단계 나열**, 순서가 없으면 **카드를 벗기고 여백·구분선으로** 묶는다.
- **한 페이지에서 같은 배치를 3번 이상 반복.** 섹션이 8개면 배치 계열은 최소 4가지.
- **N개인데 3열 그리드** → 1건만 있으면 섹션의 3분의 2가 흰 구멍이 된다.
  → **칸 수 = 콘텐츠 수.** 적으면 열을 줄이지 말고 **묶음의 폭을 줄이거나**, 카드 대신 **행 목록**으로 눕힌다.
  (열을 줄여 카드를 키우면 «1건짜리 분류»가 더 중요한 것처럼 읽힌다.)
- **제목 위 작은 대문자 라벨(eyebrow)을 섹션마다** 붙이는 것. 제목이 스스로 무슨 화면인지 못 말한다는 뜻이다.
  → 섹션 3개당 최대 1개. 웬만하면 0개.
- **`01 / 02 / 03` 섹션 번호**, `Step 1 / 단계 1` 같은 껍데기 라벨. 단계의 *내용*이 라벨이다.
- **왼쪽 큰 제목 + 오른쪽 구석에 작은 설명 문단**이 떠 있는 섹션 헤더. 설명은 제목 바로 아래로.
- **큰 숫자 + 작은 라벨 지표 블록**으로 성과를 세우는 것. 숫자가 0이 되는 날 화면이 무너진다.
  → 문장 안에 넣는다("지금 3개 접수 중").

### 2-2. 표면

- **빈 회색 박스**(이미지 미등록 자리)를 그대로 두는 것. 목록 전체가 같은 회색이 되어 표식 구실을 못 한다.
  → **분류별 기본 판**을 만들거나, 그림 자리를 아예 없앤다. 「나중에 채울 자리」는 프로토타입이 아니다.
- **모든 행에 위아래 실선**이 다 그어진 10줄짜리 스펙 표. → 3덩어리로 묶고 구분선은 덩어리 사이에만.
- **카드 안의 카드.** 항상 틀렸다.
- **그라데이션 글자 / 네온 글로우 / 순수 검정(#000)**. 강조는 굵기와 크기로.
- **채도 100% 브랜드 색을 넓은 면으로** 까는 것(특히 처리 화면). 브랜드 색은 **행동·선택·상태**에만.
- **아이콘 대신 이모지.** 아이콘은 한 세트에서 같은 굵기로 가져온다.
- **장식용 색 점**(모든 목록·내비 항목 앞의 작은 동그라미). 실제 상태를 말할 때만.
- **가운데 점(`·`)을 모든 구분자로** 쓰는 것. 한 줄에 하나까지.

### 2-3. 글

- **줄표(—) 전면 금지.** AI가 쓴 티가 가장 크게 나는 한 글자다. 마침표·쉼표·괄호·줄바꿈으로 푼다.
- **가짜 정밀 숫자**(92%, 4.1배, 2,071명). 실제 데이터가 아니면 **목업임을 표시**하거나 쓰지 않는다.
- **가짜 이름·가짜 회사**("홍길동", "김철수", "Acme", "넥서스"). 도메인에 맞는 그럴듯한 이름으로.
- **의미 없는 동사**("혁신적인", "seamless", "차원이 다른"). 구체 동사만.
- **같은 뜻의 CTA가 여러 개**("문의하기" + "상담 신청" + "지금 시작"). **의도 하나에 문구 하나**, 화면 전체에서 같은 말.

## 3. 데이터가 적을 때 레이아웃이 무너지지 않는가 (가장 자주 새는 자리)

`ux-checklist.md` A의 **빈 상태**는 "0건일 때 무엇을 보여줄까"를 잡는다. 여기는 그 **바로 옆칸** —
**0건도 아니고 꽉 찬 것도 아닌 «1~2건»** 이다. 프로토타입은 항상 데이터가 꽉 찬 상태로만 그려지기 때문에
운영 첫 달에 이 자리가 전부 터진다.

기획서에 이렇게 적는다:

| 조건 | 시스템 동작 | 화면에 보이는 것 |
|---|---|---|
| 그리드형 영역에 항목 **1~2건** | 정상 응답 | 열 수를 줄이지 않고 **묶음 폭을 줄여** 빈 칸을 없앤다. 빈 칸에 「준비 중」 타일을 채우지 않는다 |
| 목록 항목 **0건** | 정상 응답 | 안내 문구 + 다음 행동 (`ux-checklist.md` A) |
| 집계값을 **못 가져옴** | 조회 실패 | 「0」이 아니라 **자리를 비운다.** 0과 미집계는 다른 사실이다 |
| 이미지·로고 **미등록** | 정상 응답 | 분류별 기본 판. **이니셜 한 글자로 로고를 대신하지 않는다**(진짜 로고인 줄 읽힌다) |
| 제목·설명이 **아주 긺 / 아주 짧음** | 정상 응답 | 말줄임 줄 수를 지정. 짧을 때 아래 요소가 위로 딸려 올라오지 않게 |

## 4. 프로토타입 사전점검 (받자마자 5분, 기계적으로)

작성자(AI)가 아니라 **PM이** 훑는다. 한 줄이라도 «아니오»면 아직 안 된 것이다.

**모드·구성**
- [ ] 이 화면의 **모드**(§1)를 한 줄로 말할 수 있나? 처리 화면에 설득 화면의 장식이 들어가 있지 않나?
- [ ] 같은 배치가 3번 이상 반복되지 않나?
- [ ] 항목 수가 **1건일 때**도 그려봤나? 흰 구멍이 남지 않나? (§3)
- [ ] 화면의 **주된 행동이 하나로 보이나?** 같은 무게의 버튼이 여러 개 늘어서 있지 않나?

**상태**
- [ ] 로딩 화면이 **실제 배치와 같은 모양**인가? (가운데 도는 원 하나로 때우지 않았나)
- [ ] 빈 상태·에러·비활성이 다 그려져 있나? 비활성에는 **왜 비활성인지**가 붙어 있나?
- [ ] 누름(`:active`)·올림(`:hover`)·키보드 포커스가 눈에 보이나?

**글**
- [ ] 화면의 **모든 문자열**을 소리 내 읽어봤나? 말이 안 되는 문장·귀여운 척하는 문구가 없나?
- [ ] **줄표(—)가 0개**인가?
- [ ] 같은 뜻의 CTA 문구가 화면에 하나뿐인가?
- [ ] 숫자·이름·회사명이 **진짜이거나, 목업이라고 표시**돼 있나?

**대비·크기**
- [ ] 버튼 글자가 그 버튼 배경 위에서 읽히나? (흰 버튼에 흰 글자, 사진 위 투명 버튼)
- [ ] 본문·플레이스홀더·도움말·에러 글자가 그 면 위에서 읽히나? (`ux-checklist.md` D)
- [ ] 주 버튼 문구가 데스크톱에서 **두 줄로 접히지** 않나?
- [ ] 데스크톱에서 내비게이션이 **한 줄**에 들어오나?

**반응형·모션**
- [ ] 여러 열짜리 영역마다 **좁은 화면에서 무엇을 버리는지**가 정해져 있나? (`ux-checklist.md` H)
- [ ] 페이지가 **가로로 스크롤되지 않나?** (화면 끝까지 닿는 띠가 있으면 거의 항상 여기서 샌다)
- [ ] 모든 움직임을 **한 문장으로 정당화**할 수 있나? (상태 변화·피드백·로딩·전환 중 하나)
      정당화 못 하면 뺀다. 처리 화면에서는 **페이지 진입 연출을 아예 두지 않는다.**

## 5. 프로토타입 자산·컴포넌트 참고 (외부 소스)

프로토타입에 쓸 컴포넌트·모션·3D 자산을 찾을 때 여는 목록. **채택은 "기능별 UX 2~3안"의 출처 라벨을
그대로 붙여 판단한다** — 아래는 전부 회사 DS 바깥이므로 최소 ⚠️(표준이나 커스텀 필요)에서 시작한다.

| 소스 | 무엇 | 프로토타입에서 쓸 자리 |
|---|---|---|
| [GetLayers](https://getlayers.io) | Next.js 기반 3D·인터랙션 컴포넌트 템플릿 | **설득** 모드 랜딩 시안 |
| [Skiper UI](https://skiper-ui.com) | shadcn/ui 계열 인터랙션 컴포넌트 | 카드 hover·전환 같은 **미시 인터랙션 어휘 참고** |
| [Animmaster Lib](https://animmasterlib.com) | 페이지 전환·애니메이션 소스 | 모션 «이름»을 아는 용도(구현은 개발) |
| [Vengeance UI](https://vengeanceui.com) | 다크 모드 중심 애니메이션 React 컴포넌트 | 다크 시안 참고 |
| [Craftwork Freebies](https://craftwork.design/freebies) | 무료 UI 키트·3D 일러스트 | 목업 채울 **자산** |
| [Shapefest](https://www.shapefest.com) | 고화질 3D 도형 라이브러리 | 빈 이미지 자리를 대신할 **자산** |
| [Spline](https://spline.design) | 코드 없이 3D·인터랙션 제작 | 시안용 키비주얼 직접 제작 |

> **경고 두 줄.**
> ① 여기서 가져온 컴포넌트는 대부분 **회사 DS에 없다.** 시안에 넣으면 "이대로 만들어 달라"는 요구가 되고,
> 개발은 DS 밖 컴포넌트를 새로 만들어야 한다 → **넣기 전에 개발 비용을 한 번 물어본다.**
> ② 3D·화려한 모션은 **설득/체험 모드에서만** 값을 한다. 처리 화면에 넣으면 느려지고 시선만 뺏는다.

## 참고: 두 스킬에서 **가져오지 않은 것** (그리고 왜)

- **색 팔레트·폰트 지정**(taste-skill §4.1 폰트 추천, §4.2 팔레트 금지 목록) → 회사 DS와 자리 다툼.
  색·폰트는 `domain-context.md`가 정본이다.
- **다이얼(DESIGN_VARIANCE·MOTION_INTENSITY·VISUAL_DENSITY) 수치 조절** → 프롬프트 튜닝 장치라 기획서에 쓸 게 없다.
  대신 §1 «모드»가 같은 일을 PM 언어로 한다.
- **구현·성능 항목**(Core Web Vitals, useEffect 정리, z-index, 번들) → 개발·QA 몫.
- **`impeccable` / `taste-skill` 설치와 명령어 체계**(`/impeccable craft` 등) → 이 kit은 프롬프트 도구가 아니라
  **PM이 읽고 판단하는 기준**이다. 도구를 깔고 싶으면 각 레포의 설치 안내를 따로 따른다.
